# DesignBook Studio

Unity プロジェクト内の設計書を閲覧・編集する Windows デスクトップアプリです。Markdown を文章の正本、JSON を構造化データの正本として扱い、既存ファイルを直接読み書きします。設計書を管理するための別のデータベースや複製は作成しません。

Tauri 2、React、TypeScript、Rust、Milkdown/Crepe を使用しています。

## 主な機能

- Markdown と JSON の閲覧・編集・保存、外部ファイルの変更検知。
- Markdown の表や Mermaid 図の表示。
- JSON フィールドの編集、JSON Schema による検証、フィールド ID の重複検査。
- ファイル名と本文の検索、一致箇所への移動と強調表示。
- 文書とフォルダーの作成、移動、名前変更、削除。
- 画像の挿入・置換、相対パスでの保存、参照切れの検知。
- Git の変更一覧、コミット、プッシュ、ブランチ・リモート・追跡先の管理。
- ファイル履歴と JSON フィールド単位の履歴。

## プロジェクトを開く

「プロジェクトを開く」から Unity プロジェクトのルートを選択します。選択先には、次の項目が必要です。

- `Assets` ディレクトリ。
- `ProjectSettings/ProjectVersion.txt`。
- そのプロジェクトを含む既存の Git リポジトリ。

Unity プロジェクトのルートと Git リポジトリのルートは別々に識別します。Unity プロジェクトがリポジトリ内のサブディレクトリにあっても開けます。アプリが Git リポジトリを自動で初期化することはありません。

設計書ディレクトリは、選択した Unity プロジェクト内の次の候補から検出します。

`DesignDocs`、`Documentation`、`DesignDocuments`、`Design Documents`、`design-docs`、`docs/DesignDocs`、`docs/design`、`docs`

正常に開いたプロジェクトのパスはアプリのローカル設定に保存します。次回起動時にはパスを再検証し、実際のファイルツリーと Git 状態を読み直します。パスが存在しない場合や読み取り権限がない場合はエラーを表示し、別のプロジェクトを選択できます。アプリのデータを消去すると、この設定も失われます。

### 設計書ディレクトリがない場合

設計書ディレクトリがなくても、有効なプロジェクトを開けます。空の状態から作成プレビューを開くと、次の構成を確認できます。

```text
DesignDocs/
├── README.md
├── 00_総合設計/
├── 01_画面イメージ/
├── 02_処理仕様/
├── 03_項目仕様/
├── 04_API_LDI/
├── 05_世界観・ゲームルール/
├── 06_開発規約/
└── images/
```

「確認して作成」を押すまで何も作成しません。作成前に Git 状態と対象パスを再確認し、既存ファイルの上書きやシンボリックリンクなどとの競合を防ぎます。大量の空白文書は生成しません。

## 設計書の閲覧と編集

文書は最初に閲覧専用で開きます。本文をクリックしても編集モードには入りません。「編集」を押した場合だけ Markdown、JSON の原文・フィールド、画像を変更できます。

「閲覧に戻る」は未保存の編集を破棄しません。変更を残すには保存してください。保存時には原子的な書き込みを行い、外部で変更されたファイルとの衝突も検知します。

### ファイルツリーの操作

- フォルダーを選択してから新規作成すると、そのフォルダー内に文書やフォルダーを作成します。
- 文書やフォルダーを別のフォルダーへドラッグすると移動できます。
- 右クリックから名前変更・削除を実行できます。
- 未保存の編集や未確認の外部変更がある文書、およびその親フォルダーの操作は保護されます。

設計書ルート自体の変更、範囲外へのアクセス、パストラバーサル、シンボリックリンクや Windows ジャンクションを経由した操作、重名による上書き、自分自身や子孫への移動を拒否します。

**削除は確認後の完全削除です。ごみ箱には移動しません。** フォルダーを削除すると、その内容も削除されます。取り消し機能はありません。

移動・名前変更時に Markdown や JSON の相対リンクを自動で書き換えることはありません。必要に応じて参照先を修正してください。

### 設計書の検索

ファイル名と保存済みの Markdown・JSON 本文を検索します。結果はファイルごとにまとまり、一致した行・列と前後の文章を表示します。

結果をクリックすると、通常の閲覧表示を維持したまま対応する段落や表のセルへ移動し、一致語を強調します。原文を確認したい場合は「原文を表示」を選択します。

- 大文字・小文字を区別しない文字列検索です。正規表現には対応していません。
- 検索語は最大 200 文字、対象ファイルは各 5 MB まで、結果は先頭 1,000 件までです。
- 未保存の編集内容は検索対象に含まれません。
- 読み取れない文書や大きすぎる文書は通知します。検索後に文書が変わった場合は再検索を案内します。

### 画像と履歴

画像は設計書ディレクトリ内の `images/` に追加し、相対パスで参照します。画像の置換と参照切れの検知にも対応しています。

履歴ではコミットの日時を秒まで表示します。表示例は `2026-10-29 23:15:03` です。タイムゾーンの接尾辞は表示しません。

## Git の操作

右上の Git 管理画面から操作します。「保存」「Commit」「Push」はそれぞれ独立しています。

| 操作 | 実行内容 |
| --- | --- |
| 保存 | 編集した実ファイルを保存します。コミットは作成しません。 |
| Commit | 設計書範囲の変更をステージし、ローカルコミットを作成します。 |
| Push | 選択したブランチの既存コミットをリモートへ送信します。自動ステージ・自動コミットは行いません。 |
| Fetch | リモートの参照を取得します。作業ファイルは変更しません。 |
| Pull | 作業状態を検査し、取得後に早送り更新が可能な場合だけ反映します。 |

### Commit と Push の手順

1. 設計書の編集を保存します。
2. Git 管理画面でコミットメッセージを入力し、Commit を実行します。
3. 実際に作成されたコミットのハッシュと、更新された変更一覧を確認します。
4. 送信元のローカルブランチ、送信先のリモートとブランチを選択します。
5. 「送信先を安全確認（読み取り専用）」を実行します。
6. 検証後に Push を実行し、最終確認で送信内容を確認します。

Commit の対象は設計書範囲です。Unity のその他の変更とは分けて表示し、設計書以外のステージ済み変更を巻き込みません。成功時には実際の新規コミットを確認し、Git 状態を読み直します。

**Push は選択ブランチの未送信コミット全体を送信します。直前のコミットや設計書だけに限定されるわけではありません。** 未コミットの変更は送信されず、そのまま残ります。作業ツリーに未コミット変更がある場合は、該当ファイルを警告として表示します。

追跡先（upstream）がなくても、リモートと送信先を明示すれば初回 Push を実行できます。成功後に追跡先を設定するかどうかも選択できます。

送信先の検証ではリモート参照を読み取り、自動 Fetch は行いません。送信元・送信先の変更や Commit・Push 後は再確認が必要です。Push の直前にも再検証し、リモートの先行、履歴の分岐、履歴を検証できない状態、送信するコミットがない状態では停止します。force push は提供しません。ボタンが無効な場合は理由を画面に表示します。

### ブランチ・リモート・追跡先

「詳細 Git 管理」で、実際のローカルブランチ・既知のリモートブランチ・追跡先を確認できます。ブランチの作成と切り替え、リモートの追加・変更・削除、追跡先の設定、Fetch、Pull を個別に操作できます。

ブランチ切り替えや Pull は、未保存の編集、未コミット変更、履歴の分岐などを検査します。Pull は早送り更新だけに対応します。追跡先が設定済みでも履歴が取得できない場合は「未設定」と区別し、先行・遅延数を未確定として表示します。

すべての Git 操作は、現在開いているプロジェクトから解析した実際のリポジトリルートで実行します。ブランチ名やリモート名は固定しません。認証情報を含む URL などは表示時に秘匿します。

## データ保護

- プロジェクトを開くときは、ファイルの読み取りと Git 状態の確認だけを行います。
- ユーザーの操作なしに設計書の作成、Git の初期化、Commit、Push、Fetch、同期を実行しません。
- 設計書の読み書きは、選択した Unity プロジェクト内の認可済み設計書ディレクトリに限定します。
- Git の操作対象と設計書の操作対象を別々に管理します。
- 保存に失敗した場合に元ファイルを破壊しないよう保護します。

## 開発環境

Windows での開発には次のものが必要です。

- Git for Windows。
- Vite 8 の動作要件を満たす Node.js と pnpm。
- Rust の安定版、Rustup、Cargo。
- Rust の `x86_64-pc-windows-msvc` ターゲット。
- Visual Studio 2022 Build Tools の「C++ によるデスクトップ開発」、MSVC の x64/x86 ビルドツール、Windows SDK。
- Microsoft Edge WebView2 Runtime。

### 開発版を起動する

```powershell
git clone https://github.com/Ron0609/DesignBookStudio.git
cd DesignBookStudio
pnpm install
pnpm tauri dev
```

既に取得済みの場合は、そのプロジェクトディレクトリで実行してください。

開発モードは Vite の 5173 番ポートを固定使用します。使用中の場合は起動を停止します。正式な Windows ビルドは単一起動に対応し、再起動時には既存のウィンドウを前面に表示します。

フロントエンドだけを確認する場合は `pnpm dev` を使用できます。この場合はサンプル表示となり、実ファイルの保存や Git 操作は利用できません。

### 配布用の実行ファイルを作成する

```powershell
pnpm tauri build --no-bundle
```

通常の出力先は `src-tauri/target/release/designbook-studio.exe` です。`CARGO_TARGET_DIR` を設定している場合は、その設定に従います。設定済みのインストーラーも作成する場合は `pnpm tauri build` を使用します。

配布には Tauri CLI で生成した実行ファイルを使用してください。`cargo build --release` だけでは、本番用ページの組み込みに必要な設定が有効になることを保証できません。

### テストと確認

```powershell
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
pnpm test
pnpm lint
pnpm build
```

通常の端末で MSVC を認識しない場合は、インストール済みの Visual Studio Developer Command Prompt から実行してください。

Git の書き込みを伴うテストには、独立した一時リポジトリとローカルのテスト用リモートを使用します。自動テストの成功と、実際のデスクトップウィンドウでの操作確認は別々に扱います。検証範囲は [テスト計画](docs/TEST_PLAN.md) を参照してください。

## 既知の制限と未実装項目

- 外部 JSON Schema `$ref` は無効です。
- JSON Schema の編集・生成は未実装です。
- 画像の切り抜き・サイズ変更は未実装です。
- Markdown の文字サイズ・文字色の拡張は未実装です。
- 設定・ヘルプ・属性画面の一部は未実装です。
- 文書の移動・名前変更に伴う相対リンクの自動修正と、削除の取り消しには対応していません。
